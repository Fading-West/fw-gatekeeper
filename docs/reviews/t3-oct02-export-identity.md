# Keep stable attendance identifiers in downloaded records

Rank 25; high impact is an engineering estimate, with no measured usage claim. Activity and hours CSVs previously exported only mutable worker names/department labels. Distinct workers with matching names were separate internally but indistinguishable in downloaded hours rows, and effective corrections could not be matched back to source records. Both normal export actions now append stable worker IDs. Activity exports also append their event ID and correction ID; synthetic effective events retain their `correction:<id>` identity plus the underlying correction ID. Current employee IDs are supplemental labels, not stable join keys or historical identity snapshots. Removed/missing roster rows keep stable identifiers and leave the employee label blank.

Existing column order, effective-event selection, timestamp display, absolute-time ordering, overnight pairing, totals, and ambiguous-hour withholding are preserved. The joined API payload now exposes the current employee ID without an extra query or schema migration. All additional cells use the existing CSV sanitizer. The UI explains the matching key and current roster label.
