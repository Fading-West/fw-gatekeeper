# Truthful department/day schedule assignments

Multiple active schedules in the applicable department/day tier previously selected the first database row. Briefing counts, missing/late/clock-out classifications and suggested corrections could therefore use an arbitrary shift. A shared resolver now reports unique, none or ambiguous. Department matches take precedence; defaults apply only when there are no matching department schedules. Multiple schedules in the effective tier never acquire an invented priority or fall through to a default. Schedule creation/update remain available and unchanged.

Unavailable assignments appear in normal Briefing warnings, readiness source risks, exception queues and closeout coverage acknowledgement. No matching schedule does not establish that a worker was expected or absent. Attendance classifications/counts include only unique supported assignments. Raw/effective activity and scan-sequence exceptions remain available, while schedule-derived corrections are unavailable for unresolved assignment/range issues. Manual evidence-backed attendance corrections remain governed by the existing source/authorization contract. Canonical coverage evidence retains candidate source IDs/ranges even after an exception disposition, for combined blocker acknowledgements.

For compatibility with old92, coverage gaps caused entirely by unique assignments with unsupported time ranges retain readiness risk ID `schedule:unsupported` and action ID `schedules:unsupported`. Missing or ambiguous assignments, including mixtures with unsupported ranges, use `schedule:unavailable` and `schedules:unavailable`. Missing-only coverage remains a warning; any ambiguity or unsupported range remains critical. The closeout `schedule_coverage` blocker and its post-disposition acknowledgement requirement remain unchanged. All inherited unsupported-time and daily attendance regression assertions are preserved; source fixtures additionally assert both ID contracts and mixed-gap severity.
