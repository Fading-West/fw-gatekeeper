# Deduplicate schedule creation intents

Rank15; high attendance-integrity benefit is an engineering estimate. Repeated submit and response-loss retries could create duplicate attendance rules. The normal schedules form now prevents simultaneous saves, retains an uncertain creation request ID in tab session storage and acknowledges it only after a valid saved ID response. The authenticated mutation indexes creator plus request, saves the immutable original intent and returns the original schedule ID on matching replay, even if that schedule was later edited or removed. Conflicting reuse fails with409. Intentional subsequent creation receives a new ID.

Optional fields/index support existing rows and legacy API callers without migration. Only request-bearing callers receive replay guarantees; the updated normal UI always sends a request ID. Regression coverage includes concurrent/repeated create, conflicting replay, removed schedule replay, intentional second intent, unauthorized roles and client uncertain-ID persistence. Source only: tests, exact types/lint/build, normal admin app interrupted/repeated actions, CI and combined integration gates remain pending runtime admission. No deployment or real data.
