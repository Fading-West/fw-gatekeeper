# Reject invalid kiosk policy without losing offline operation

Local overrides previously accepted NaN/string recognition settings and treated every unsupported KIOSK_TYPE as auto. The shared, native-free kiosk_policy validator now requires explicit entry/exit/auto, actual booleans, positive integer frame/window/streak values, and finite numeric thresholds/timers within their documented domains. No settings are silently coerced. Zero debounce/display durations remain supported; blink deadlines and threshold must be positive.

Consumer representation correction: embedding windows must fit sys.maxsize, the deque maxlen/Py_ssize_t range. Debounce durations must be representable by the actual timedelta(minutes=...) consumer. These are implementation representation bounds, not new site operating limits. Synthetic regressions cover huge integers and finite durations that overflow their consumers, degraded startup before native work/thread/matcher creation, and retained supervised manual fallback.

Invalid scan policy starts the local web UI and database, publishes policy_ok=false with setting names in policy_errors, pauses automatic scanning before model/camera initialization, and keeps synchronization and durable queues available. Restart after correcting config_local.py. Recognition-only faults allow existing supervised local manual attendance. An invalid KIOSK_TYPE blocks implicit manual action selection; a supervisor may still submit an explicit validated clock_in/clock_out. Unsupported explicit actions are rejected. No credential values appear in the policy report.

Scope: master-based validation and degraded workflow only. Preserve PR99 vector validity, PR100 fresh face evidence, PR104 required blink enforcement, rank1 durable manual receipts, rank10 setup policy preservation, rank11 camera recovery, and rank19 startup fallback on composition. Neither policy repair nor recognition recovery creates an attendance event.
