# Show protected sync authorization faults independently of reachability

Public /api/health can succeed while a protected route denies the kiosk key. SyncAuthHealth records roster download, roster acknowledgement, attendance upload, and recognition upload independently. A 401/403 marks that phase denied; only a later validated successful response from that same protected phase clears it. Other successful phases, malformed/partial 2xx responses, public reachability, network failure and 5xx responses cannot erase a denial. Validation includes durable roster application, complete attendance/recognition batch acknowledgements, and an acknowledged roster receipt with its applied timestamp.

State is process-local: denial observations are not durable across restart. A fresh process reports every phase unknown and aggregate sync_auth_ok=null until all four phases validate; public health alone only establishes server reachability. The footer then says protected sync is not fully confirmed, never Synced/Connected/green. An idle phase may remain unknown until it has a real request, and an observed denial persists until that phase succeeds. This is the actual observation boundary, not a claim that restarting repaired credentials.

Local /health and the kiosk footer show authorization needs attention, the affected workflows, and existing queue/rejection counts even while the public server is reachable. The sync worker reports faults at every cycle boundary, including interrupted cycles. Scanner/manual local attendance remains operational. No PIN or API-key values are exposed. An idle phase with no queued requests retains its observed fault until that phase actually succeeds again.

Scope: master-based protected-response observations and local health/UI only. Preserve old PR95 roster commit acknowledgements, PR97 complete batch acknowledgements, PR99 vector validation, PR107 recognition quarantine/acks, and rank12 independent sync phases on composition. The recognition complete-ack validator matches the preserved PR107 contract; it is a required existing dependency, not a new counted improvement. Move both observations into PR107's _upload_recognition request helper: denial before response handling, validated success after the complete-ack check and durable mark. Keep rank12's complete two-commit range. A denied/malformed request neither acknowledges nor quarantines rows.

Regression source: test_t3_sync_auth_health.py exercises actual protected request functions with synthetic response/database adapters, separate phase recovery, public health masking, queue retention, and interrupted cycle reporting. test-t3-sync-auth-health.mjs evaluates the actual footer branch with online/offline public reachability and simultaneous retained authorization faults. No live credentials, real attendance, native models or network calls are required by these fixtures.
